# 골라담기 옵션 UI — 구현 방식

카페24 상품 상세페이지에 Figma 시안 기반 "골라담기" 커스텀 옵션 UI를 얹는 패키지입니다.
**구매/장바구니/금액 계산은 전부 카페24 기본 로직에 위임**하며, 이 UI는 카페24 기본
옵션을 대신 "조작"하는 역할만 합니다.

**구현 내용 확인 URL** — https://egnisgo.cafe24.com/product/detail.html?product_no=11

설치 절차는 [docs/INSTALL.md](docs/INSTALL.md), 정적 리소스 경로 규칙은
[docs/PATH_RULES.md](docs/PATH_RULES.md) 를 참고하세요.

## 1. 옵션 UI 구현 방식

### 마운트 지점 하나로 JS가 전부 렌더링

스킨에는 빈 `<div id="pickOptionRoot"></div>` 만 넣습니다.
카드·맛 목록·스테퍼 마크업은 HTML에 두지 않고, `pick_option.js` 가 설정값
(`counts`, `flavors`)을 읽어 런타임에 그립니다. 설정만 바꾸면 마크업 수정 없이
카드와 맛 목록이 바뀝니다.

### 기본 옵션은 지우지 않고 가린다

카페24 기본 옵션 영역은 CSS `display:none` 으로 **화면에서만 감춥니다.**
골라담기가 이 안의 옵션 버튼/`<select>` 를 조작하므로 DOM을 삭제하면 담기가 동작하지 않습니다.
구매 폼(`<div module="product_detail">`), 선택상품 목록(`#totalProducts`), 수량,
총금액, 구매 버튼도 그대로 둡니다.

### 화면 흐름

1. 개입수 카드 클릭 → 맛 선택 패널 열림 (모바일은 바텀시트)
2. 스테퍼로 합계 = `count` 가 되면 `선택완료` 활성화, 초과하면 툴팁
3. `선택완료` → 카페24에 옵션값을 선택시킴 → 카페24가 선택상품 행 생성·금액 계산
4. 담긴 행의 옵션 텍스트는 `30개입_1` → `30개입` + 맛 구성 줄로 **표시만** 정리

상태(선택한 카드, 맛별 수량, 개입수별 사용 횟수)는 JS가 들고 있고,
이벤트는 개별 요소가 아니라 컨테이너에 위임해 처리합니다.

### 파일 구성

| 파일 | 역할 |
| --- | --- |
| `js/option_config.js` | 모든 설정값 (개입수·맛·문구·셀렉터·모바일) |
| `js/pick_util.js` | 공용 헬퍼 (셀렉터 탐색·템플릿 치환·DOM 생성) |
| `js/cafe24_bridge.js` | 카페24 연동 전담 (옵션값 파싱·컨트롤 탐지·행 관측) |
| `js/pick_option.js` | 골라담기 상태 관리 + 렌더링 |
| `js/page.js` | 탭 전환, 모바일 바텀시트, 합계 표시 동기화 (카페24 값 읽기 전용) |
| `css/pick_option.css` | 골라담기 UI 스타일 |
| `css/custom_detail.css` | 페이지 전체 스타일 |
| `html/detail.html` | 전체 스킨 템플릿 (카페24 모듈 보존) |

전역은 `window.PickOption` 하나만 사용하고 나머지는 IIFE 내부에 둡니다.
JS 로드 순서는 반드시 아래와 같습니다.

```
option_config.js → pick_util.js → cafe24_bridge.js → pick_option.js → page.js
```

## 2. 외부 설정 JS 구조

`js/option_config.js` 는 전역 객체 하나에 **순수 데이터만** 담습니다.
함수·조건 분기·구매 로직은 넣지 않고 동작은 전부 `pick_option.js` 에 둡니다.
다른 작업자가 이 파일의 값만 바꿔도 UI가 동작하는 것이 목표입니다.

```js
window.PICK_OPTION_CONFIG = {
  counts: [...],       // 1) 개입수 카드
  unitSize: 10,        // 2) 스테퍼 1당 개수
  flavors: [...],      //    맛 목록
  texts: {...},        // 3) 토스트·툴팁·타이틀 문구
  cafe24: {...},       // 4) 스킨 연동 셀렉터
  mobile: {...},       // 5) 모바일 동작
  freeShipGoal: 40000, // 6) 무료배송 기준 금액
  debug: false
};
```

### counts — 개입수 카드

| 키 | 설명 |
| --- | --- |
| `key` | 내부 상태 키 (`PickOption.getState()` 의 키) |
| `label` | 카드 표시명. **옵션값의 suffix 앞부분과 일치 필수** (`30개입_1` → `30개입`) |
| `count` | 맛 선택 합계 목표 개수 |
| `price` / `discount` / `unitPrice` | 카드 가격 표기 (표시용) |
| `badge` | `{ text, type: 'primary'│'danger' }` 또는 `null` |
| `maxAdd` | 담기 가능 최대 횟수 = 관리자에 등록한 suffix 개수 |

`label` / `maxAdd` / `price` 는 카페24 관리자 옵션값·품목 설정과 일치해야 합니다.
표시 가격은 화면용이고 결제 기준은 카페24 품목입니다.

### flavors — 맛 목록

| 키 | 설명 |
| --- | --- |
| `name` / `meta` | 표시명, 부가정보(kcal·단백질) |
| `img` | 썸네일 경로 (`/web/upload/pick_option/...`) |
| `badge` | 이름 위 강조 문구 (예: `신제품 출시!`) |
| `soldOut` | `true` 면 품절 처리(비활성) |

### texts — 문구

토스트·툴팁·타이틀 문구를 모아 둡니다.
`{selected} {remain} {label} {count} {max}` 플레이스홀더가 자동 치환됩니다.

### cafe24 — 스킨 연동 셀렉터

각 항목은 **후보 배열**이며 페이지에 존재하는 첫 번째를 사용합니다.
스킨이 다르면 개발자도구로 실제 요소를 확인해 배열 맨 앞에 추가합니다.

| 키 | 설명 |
| --- | --- |
| `optionSelect` | 기본 옵션 `<select>` 후보 (셀렉트형에서만, 자동 탐지가 우선) |
| `productRows` / `rowItem` | 선택상품 목록 컨테이너 / 행 |
| `rowOptionText` | 행 내 옵션명 요소 — suffix를 지우고 맛 구성을 표시 |
| `writeFlavorToExtraInput` | 추가입력 옵션에 맛 구성 문자열 기록 여부 |
| `buyButtons` | 미선택 구매 클릭 시 토스트를 띄울 버튼들 |

### mobile

`mode: 'sheet'`(바텀시트, 시안 기준) 또는 `'inline'`.
`bottomOffset` 을 하단 고정 구매바 높이(px)로 맞추면 시트·토스트가 버튼과 겹치지 않습니다.

## 3. 카페24 옵션과 동기화한 방식

### 전제 — 옵션값을 suffix로 등록

같은 개입수를 여러 번 담을 수 있도록 관리자에서 옵션값을 suffix까지 붙여 등록합니다.
suffix 개수 = 그 개입수를 담을 수 있는 최대 횟수(`maxAdd`)입니다.

```
10개입_1, 10개입_2, 30개입_1, 30개입_2, 50개입_1, 50개입_2, 100개입_1
```

### 옵션 컨트롤 자동 탐지

옵션 표시방식마다 마크업이 완전히 다르므로, 클래스명이 아니라 **옵션값 텍스트**로
조작 대상을 찾습니다. `counts[].label` + `_숫자` 패턴에 맞는 요소를 문서에서 검색합니다.

| 표시방식 | 탐지 대상 | 담기 동작 |
| --- | --- | --- |
| 텍스트버튼형 / 이미지버튼형 | 값 텍스트(또는 `value`/`rel`/`data-value`)를 가진 `<a>` `<button>` `<input>` | 해당 요소를 네이티브 `click()` |
| 셀렉트형 | 옵션값을 가진 `<select>` | `value` 설정 + `change` 트리거 |

버튼과 select 가 둘 다 있으면 **버튼 클릭을 우선**합니다. 버튼을 클릭해야
카페24가 버튼 UI의 선택 상태까지 갱신하기 때문입니다. select 값만 바꾸면
행은 생기지만 기본 옵션 UI는 선택되지 않은 것처럼 남습니다.

탐지 범위에서 `#pickOptionRoot` 와 선택상품 목록 영역은 제외합니다
(담긴 행에도 `30개입_1` 텍스트가 있어 옵션 버튼으로 오인될 수 있기 때문).

### 담기 — 이후는 카페24에 위임

`선택완료` 를 누르면 아직 쓰지 않은 suffix 옵션값 하나를 카페24에 선택시킵니다.
이후 **선택상품 행 생성·금액 계산·장바구니 전송은 전부 카페24 기본 로직**이 처리합니다.
담기 성공 판정은 행 개수 증가가 아니라 **해당 옵션값이 담긴 행을 직접 확인**하는 방식입니다
(기본 스킨은 `<tbody>` 가 여러 개라 개수 비교가 어긋납니다).
담기 처리 중에는 `busy` 플래그로 버튼을 잠가 연타를 막고, 행 생성을 확인한 뒤 풉니다.

### 기본 동작을 막지 않는다

옵션 선택 없이 구매·장바구니를 누르면 capture 단계에서 토스트만 띄우고,
행이 하나라도 있으면 카페24 기본 동작을 그대로 통과시킵니다.
커스텀 구매바 버튼은 `data-proxy` 로 카페24 원본 버튼을 대신 클릭할 뿐,
자체 폼 전송이나 주문 API 호출은 구현하지 않습니다.

### 연동 상태 확인

```js
PickOption.diagnose()  // 인식된 옵션값과 조작 방식(버튼 click / select+change)을 표로 출력
PickOption.getState()  // { qty10: { label:'10개입', used: 1, max: 2 }, ... }
PickOption.rescan()    // 옵션값/목록 강제 재동기화
```
