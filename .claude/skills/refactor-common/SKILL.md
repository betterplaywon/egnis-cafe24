# 공통화 · 코드 분리

목표는 **읽기 쉬운 최소 구조**입니다. 중복을 없애되, 새 추상화 레이어를 만들지 않습니다.

## 1. 중복 찾기

변경 범위 안에서 다음을 확인합니다.

```bash
git diff --name-only && git status --short
```

훑어볼 것:

- 같은 형태의 DOM 조회/생성이 2회 이상 나타나는 곳
- 같은 `replace` / 문자열 치환 체인
- 같은 이벤트 바인딩 패턴
- 같은 카페24 요소 조작(select 값 변경 + `change` 디스패치, 버튼 `click()`)
- 같은 가드 조건(`if (!el) return;` 앞에 붙는 동일한 탐색 로직)

## 2. 추출 판단

추출한다:

- 2회 이상 반복되고, **함께 바뀔** 코드
- 이름을 붙이면 호출부가 명확히 읽히는 코드

추출하지 않는다:

- 모양만 닮았고 변경 이유가 다른 코드
- 한 곳에서만 쓰이는 1~2줄 래퍼
- 지금 필요 없는 확장 포인트·옵션 파라미터

## 3. 분리 기준

- 한 함수는 한 가지 일. 렌더링 / 상태 변경 / 카페24 연동을 섞지 않습니다.
- 대략 50줄을 넘으면 의미 단위로 쪼갭니다.
- 값은 [js/option_config.js](../../../js/option_config.js), 동작은
  [js/pick_option.js](../../../js/pick_option.js). 이 경계를 넘지 않습니다.
- 공개 API는 `window.PickOption` 하나. 나머지는 IIFE 내부에 둡니다.
- 새 파일은 기존 파일이 명확히 두 책임을 갖게 될 때만 만듭니다.

## 4. 안전 확인

리팩터링은 **동작을 바꾸지 않아야** 합니다. 끝나면 반드시:

```bash
node test/test.js
node test/test-textbutton.js
node test/test-basicskin.js
node test/test-page.js
```

4개 모두 통과해야 완료입니다. 실패하면 결과를 그대로 보고합니다.

## 5. 마무리

리팩터링 과정에서 만든 임시 코드·비교용 사본이 남아 있으면
`cleanup-temp` 스킬로 정리한 뒤 완료를 보고합니다.

## 하지 말 것

- 카페24 기본 구매/장바구니 로직을 감싸거나 재구현하는 방향의 "정리"
- 카페24가 만든 DOM·이벤트 삭제 (숨김은 CSS로만)
- 옵션과 무관한 영역(이미지·상세설명·배너·구매버튼 외형) 손대기
- 요청받지 않은 범위까지 넓히기
