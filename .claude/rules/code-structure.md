# 코드 구조 규칙

## 1. 비슷한 로직은 공통 모듈로

같은 형태의 코드가 **2회 이상** 반복되면 공통 함수/모듈로 추출합니다.

추출 대상이 되는 대표 패턴:

- **후보 셀렉터 탐색** — `config.cafe24.*` 는 셀렉터 배열입니다. "배열을 돌며 페이지에
  존재하는 첫 번째 요소를 반환"하는 로직은 한 곳(`findFirst` 류)에만 둡니다.
- **템플릿 문자열 치환** — `{label}` `{count}` `{remain}` 같은 플레이스홀더 치환은
  단일 헬퍼로 처리하고, 문구마다 개별 `replace` 체인을 쓰지 않습니다.
- **DOM 생성** — 카드/맛 아이템처럼 반복되는 마크업은 렌더 헬퍼 하나로 만듭니다.
- **이벤트 위임** — 개별 요소마다 리스너를 붙이지 말고 컨테이너에 위임합니다.
- **카페24 요소 조작** — `<select>` 값 변경 + `change` 디스패치, 버튼 `click()` 등은
  전용 함수로 감싸 호출부에서 반복하지 않습니다.

추출하지 않아도 되는 경우: 우연히 모양만 닮았고 변경 이유가 다른 코드.
같이 바뀌지 않을 코드를 억지로 합치지 않습니다.

## 2. 적당한 수준에서 분리

- 함수 하나는 **한 가지 일**만 합니다. 렌더링·상태 변경·카페24 연동을 한 함수에
  섞지 않습니다.
- 함수가 길어지면(대략 50줄 이상) 의미 단위로 쪼갭니다.
- 다만 **과도한 추상화는 금지**합니다:
  - 한 곳에서만 쓰이는 1~2줄짜리 래퍼 함수를 만들지 않습니다.
  - 미래에 쓸지도 모르는 확장 포인트·옵션 파라미터를 미리 만들지 않습니다.
  - 클래스 계층·플러그인 구조 같은 프레임워크를 새로 도입하지 않습니다.
- 현재 파일 구조(설정 / 옵션 로직 / 페이지 로직 / 스타일)를 유지합니다.
  새 파일은 기존 파일이 명확히 두 가지 책임을 갖게 될 때만 만듭니다.
- 전역 오염을 피합니다. 공개 API는 `window.PickOption` 하나로 한정하고
  나머지는 IIFE 내부에 둡니다.

## 3. 설정과 로직의 경계

- 값(문구·가격·개수·셀렉터·이미지 경로)은 [js/option_config.js](../../js/option_config.js) 에,
  동작은 [js/pick_option.js](../../js/pick_option.js) 에 둡니다.
- 로직 파일에 문구·셀렉터를 하드코딩하지 않습니다. 폴백이 필요하면 설정 로드부에서
  기본값을 한 번만 병합합니다.
- 설정 파일에 함수·조건 분기·구매 로직을 넣지 않습니다. 순수 데이터만 담습니다.

## 4. 카페24 연동 코드

- 스킨 DOM은 몰마다 다릅니다. 요소를 찾을 수 없을 때는 **조용히 기능을 끄고**
  (`config.debug` 일 때만 로그) 페이지를 깨뜨리지 않습니다.
- 카페24가 만든 요소를 삭제하거나 이동시키지 않습니다. 숨김은 CSS로만 합니다.
- 카페24 기본 이벤트를 `preventDefault` / `stopPropagation` 으로 막지 않습니다.
  앞단에 동작을 덧붙이는 것까지만 허용됩니다.

## 5. 정적 리소스 경로 (절대 규칙)

**CSS·JS 는 스토어프론트 경로만 사용합니다. 파일업로더 경로(`/web/upload/...`)는 금지입니다.**

파일업로더는 스킨과 다른 도메인(`ecimg.cafe24img.com`)으로 서빙되어 상품 상세페이지에서
CSS·JS 가 로드되지 않습니다. 실제로 이 경로를 쓰는 동안 스타일·스크립트가 전부 404 였고
UI 가 깨졌습니다.

| 종류 | 경로 | 로드 방식 |
| --- | --- | --- |
| CSS | `/css/module/product/*.css` | `<!--@css(...)-->` 지시자 |
| JS | `/js/module/product/*.js` | `<!--@js(...)-->` 지시자 |
| 이미지 | `/web/upload/pick_option/...` | 파일업로더 (**이미지만** 예외) |

- 이 두 경로 외의 폴더를 임의로 만들지 않습니다.
  (`/css/pick_option/`, `/js/pick_option/` 같은 경로는 존재하지 않습니다.)
- `/css/module/product/detail.css` 는 **스킨 원본 파일**입니다. 우리 스타일은
  `custom_detail.css` 로 이름을 구분해 덮어쓰지 않습니다.
  원본을 덮어쓰면 카페24 기본 모듈의 스타일이 사라져 상세페이지가 깨집니다.
- CSS 는 `<link>`, JS 는 plain `<script src>` 대신 **`@css` / `@js` 지시자**를 씁니다.
  카페24가 스킨 버전에 맞는 캐시 파라미터를 자동으로 붙여 주므로 수정 후 반영이 확실합니다.
  plain `<script src>` 는 파라미터가 없어 카페24 CDN 이 옛 파일을 계속 서빙합니다
  (실제로 이 때문에 JS 수정이 반영 안 된 적 있음 — TROUBLESHOOTING #G). 수동 `?v=`
  버전 파라미터는 매번 갱신해야 해 실수하기 쉬우므로 쓰지 않고 `@js` 로 자동화합니다.
- 스킨 템플릿(`html/*.html`)에서 `/web/upload/` 로 시작하는 `<link>` · `<script>` 를
  **새로 추가하지 않고, 발견하면 스토어프론트 경로로 되돌립니다.**
- JS 로드 순서는 항상 `option_config.js → pick_util.js → cafe24_bridge.js →
  pick_option.js → page.js` 입니다. 스니펫을 포함해 5개를 모두 로드합니다
  (`page.js` 누락 주의). `@js` 는 위치 그대로 `<script>` 로 치환돼 순서가 보존됩니다.
- 설명 주석 안에 `<!--@css(...)-->` 같은 지시자 예시를 **문자 그대로 넣지 않습니다.**
  HTML 주석은 중첩되지 않아 주석이 끊기고, 카페24가 실제 지시자로 처리할 수 있습니다.
